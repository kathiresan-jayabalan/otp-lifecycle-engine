# Research layer - data & epistemic status

This directory holds the **statistical/ML evaluation layer** that sits on top of the
deterministic compliance-as-code engine in `../src/policy/`. It answers questions the
deterministic engine cannot: *how well can a classifier distinguish compliant from
non-compliant behaviour, ahead of time, from partial signal, and how sensitive is that
performance to which controls or features are available?*

## What is real vs. synthetic here

| Artifact | Status |
|---|---|
| `../dataset/rba-sample.csv` | Explicitly invented bootstrap sample (see `../dataset/README.md`); too small (20 rows) for any classifier claim on its own. |
| `../dataset/rba-full.csv` (gitignored, fetched on demand) | Real public dataset (Wiefling et al., Zenodo 2022, doi:10.5281/zenodo.6782155) - not committed, not downloaded by default. |
| `data/generated/rba_synthetic.csv` | **Synthetic, documented, seeded** - generated by `data/generate_rba_dataset.py` from an explicit, inspectable generative model (see that file's docstring). Used because the bootstrap sample is too small for meaningful train/test evaluation and the full dataset requires an on-demand multi-GB download. |
| `data/generated/otp_timelines.csv` | **Synthetic, documented, seeded** - generated by `data/generate_otp_timelines.py`. Ground-truth labels come from a Python re-implementation of this repo's own deterministic predicates (`otp_predicates.py`), not from an external unknown source, so "ground truth" here means "what the same rules this repo enforces would decide," not an oracle. |

No experiment result in `results/` is hand-edited or backfilled to hit a target number. Every
number in `results/summary_table.md` is produced by `experiments/run_all.py` and can be
regenerated bit-for-bit with the same seed.

`experiments/risk_adaptive_policy.py` and `experiments/cross_repo_summary.py` are the two
exceptions to "everything comes from `run_all.py`": both require the sibling
`fido2-nist-mfa-research` repo checked out alongside this one (same parent directory) and its
own `research/experiments/friction_completion.py` already run, so they are run standalone
rather than wired into `run_all.py`. `risk_adaptive_policy.py` writes
`results/risk_adaptive_policy.csv` / `results/risk_adaptive_policy_per_seed.csv`;
`cross_repo_summary.py` reads that plus three of the sibling repo's result CSVs to produce
`results/cross_repo_summary.md`.

## Running

```bash
py -m pip install -r research/requirements.txt
py research/experiments/run_all.py

# optional, requires the sibling fido2-nist-mfa-research repo checked out alongside this one:
py research/experiments/risk_adaptive_policy.py
py research/experiments/cross_repo_summary.py
```

Outputs land in `research/results/` (CSVs, PNG ROC curves, and `summary_table.md`).
